## What is HonorSpy?

HonorSpy is a **World of Warcraft (Turtle WoW) PvP honor tracking dashboard** that:

1. **Aggregates player data** from multiple WoW addon contributors (~2,045 active players)
2. **Calculates weekly rank projections** based on honor standings and bracket placement
3. **Compares pre-reset vs post-reset snapshots** to determine actual RP awards
4. **Provides a web dashboard** for players to track their PvP progress

## Critical Issue Found and Resolved

### Problem
The `honorspy-api.service` was in a **crash-loop** with **81,475+ restart attempts**:
- Error: `Port 5002 is in use by another program`
- Cause: A zombie Python process (PID 4004103) from Dec 11 was holding port 5002
- The systemd service was attempting to restart every 5 seconds, failing each time

### Diagnosis Commands
```bash
# Check what's using port 5002
sudo lsof -i :5002
# Result: python3 process PID 4004103 holding port

# Check process details
ps aux | grep 4004103
# Result: opc 4004103 ... Dec11 python3 api.py
```

### Resolution
```bash
# 1. Stop the systemd service
sudo systemctl stop honorspy-api

# 2. Kill the zombie process
kill 4004103

# 3. Verify port is free
sudo lsof -i :5002
# Result: Port 5002 is now free

# 4. Restart the service
sudo systemctl start honorspy-api

# 5. Verify API is running
curl -s http://127.0.0.1:5002/api/health
# Result: {"status":"ok","timestamp":1765761670}
```

### Post-Fix Status
- **Service Status:** `active (running)` - PID 2160748
- **API Health:** `{"status":"ok"}`
- **Dashboard HTTP:** 200 OK
- **Restart Counter:** Reset to 0

## RP Formula (Honor-Based Interpolation)

The dashboard uses a calibrated formula to predict weekly RP awards:

```
award = floor + (honor_pct * spread)
where honor_pct = (player_honor - expected_min) / (expected_max - expected_min)
```

## Lessons Learned

1. **Zombie Process Detection:** When a service is in a restart loop, always check for orphaned processes holding the port (`lsof -i :PORT`)

2. **Systemd Restart Behavior:** With `Restart=always` and `RestartSec=5`, systemd will infinitely attempt restarts - the restart counter reached 81,475+

3. **Flask Development Server:** The API uses Flask's development server (not production WSGI) - noted in logs as a warning

4. **Port Binding Race:** The zombie process was started manually (Dec 11) and stayed running even when systemd service was managing api.py
